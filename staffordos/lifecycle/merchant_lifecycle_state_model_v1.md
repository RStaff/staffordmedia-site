# Merchant Lifecycle State Model v1

Status: CANONICAL_STATE_ARCHITECTURE_ONLY

Purpose: define where a merchant exists operationally across StaffordMedia.ai, ShopiFixer execution, proof, approval, deployment readiness, and Abando onboarding. This document does not create storage, APIs, UI, automation, or Shopify execution.

## State Rules

- Lifecycle state is operational truth, not merchant-facing copy.
- A state transition does not execute work by itself.
- Any transition into mutation, proof, deployment, or Abando activation must preserve merchant identity and store domain.
- Rollback evidence must exist before deployment readiness.
- Approval states must remain explicit; validation success is not approval.
