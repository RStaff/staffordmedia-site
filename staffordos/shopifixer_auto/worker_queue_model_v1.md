# Worker Queue Model v1

Status: ARCHITECTURE_ONLY_NOT_IMPLEMENTED

Purpose: define future queue topology for ShopiFixer Auto without implementing workers, automation, CI/CD, Kubernetes, or Shopify execution.

## Queue Topology

| Queue                      | Purpose                                                                              | Input artifact                                                                        | Output artifact                                                   | Failure conditions                                                                                 | Retry policy                                                        | Escalation path                                          |
| -------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------- |
| audit_queue                | Convert store evidence into bounded audit findings.                                  | Store domain, provided screenshots, public storefront evidence, or audit payload.     | Audit finding set and recommended mutation depth.                 | Missing store context, unavailable evidence, unclear merchant scope.                               | Retry only after evidence is refreshed or provided.                 | Ross review if finding may trigger mutation.             |
| theme_classifier_queue     | Identify theme archetype and confidence.                                             | Theme files, manifest, settings evidence, or recovered theme memory.                  | Theme classification record.                                      | Unknown theme, low confidence, conflicting theme signals.                                          | One retry with additional files. Then classify as Unknown/custom.   | Ross review before mutation packet creation.             |
| snapshot_queue             | Define or later capture before/after source and visual proof.                        | Approved snapshot request, theme ID, duplicate theme concept, screenshot target list. | Snapshot manifest or blocked snapshot report.                     | Missing theme ID, no duplicate theme, missing preview URL, inconsistent viewport set.              | Retry only after missing access or evidence is corrected.           | Ross review for proof gaps.                              |
| mutation_packet_queue      | Compile audit finding into a safe work packet.                                       | Audit finding, theme classification, resource gate, snapshot requirements.            | Mutation packet draft or blocked packet.                          | Broad file scope, missing rollback, missing screenshots, unclear hypothesis, prohibited operation. | No automatic retry. Revise packet manually.                         | Ross approval required before sandbox execution.         |
| codex_execution_queue      | Future sandbox-only execution of approved mutation packets.                          | Approved mutation packet and sandbox theme path.                                      | Changed files list, verification notes, blocked execution report. | Missing allowed files, scope ambiguity, live theme target, budget exceeded, validation failure.    | No silent retry. Retry requires packet update or explicit approval. | Ross review on ambiguity or budget breach.               |
| visual_qa_queue            | Review visual proof against acceptance criteria.                                     | Before/after artifact manifest, screenshots, diff images, changed files.              | QA status and risk classification.                                | Missing matching screenshots, high-risk unexplained diff, mobile regression, CTA regression.       | Retry only with corrected proof or reverted mutation.               | Ross review before merchant proof.                       |
| approval_packet_queue      | Package proof for Ross or merchant review.                                           | QA result, mutation summary, rollback reference, expected impact.                     | Approval packet draft.                                            | Technical language, unsupported claims, missing rollback safety, missing proof links.              | Revise copy and evidence.                                           | Ross approval before merchant-facing packet.             |
| rollback_queue             | Restore sandbox state or prepare rollback proof when needed.                         | Rollback trigger, original snapshot, patch diff, rollback reference.                  | Rollback proof or blocked rollback report.                        | Missing original state, incomplete diff, failed restore, unclear target theme.                     | Retry only against duplicate/sandbox state with explicit approval.  | Stop and escalate to Ross. No live changes.              |
| deployment_readiness_queue | Decide whether a reviewed sandbox mutation is eligible for separate launch approval. | Merchant approval, Ross approval, QA pass, rollback proof, deployment checklist.      | Deployment readiness record, not deployment.                      | Missing merchant approval, missing rollback, high-risk diff, unknown live theme target.            | No retry without new approvals.                                     | Ross final review. Separate deployment process required. |

## Queue Rules

- Queues pass artifacts, not permission.
- A downstream queue must reject missing upstream proof.
- No queue may mutate a live Shopify theme.
- No queue may create deployment eligibility without rollback evidence.
- Cross-merchant queue contamination is a critical failure.
